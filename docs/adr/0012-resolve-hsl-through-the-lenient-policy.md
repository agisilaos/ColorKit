# Resolve HSL through the lenient policy

`hslComponents()` will resolve through the platform color types for the current appearance, extending the split recorded in [ADR 0010](0010-resolve-legacy-luminance-leniently.md) from luminance to HSL. Reading raw `cgColor` components required at least three of them, so named SwiftUI colors, which carry no `cgColor`, and grayscale colors, which carry two, reported no value; `adjustedForMode(isDarkMode:)` and `adjustedForAccessibility(with:minimumRatio:)` both return their input when HSL is unavailable, so both were silent no-ops for every named and grayscale color. The strict snapshot cannot fix this, because it resolves through `cgColor` and reports nothing for named colors. HSL is defined on sRGB, so clamping a wider-gamut color into sRGB is the conversion this coordinate space asks for rather than a loss the caller should be shielded from; a color the platform cannot resolve at all, such as a pattern color, still reports no value.
